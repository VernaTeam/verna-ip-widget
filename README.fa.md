# ویجت آی‌پی ورنا

[English](README.md) · **فارسی**

یک ویجت کوچک برای دسکتاپ ویندوز که به یک سؤال جواب می‌ده: **ترافیک من از کجا بیرون می‌ره، و آیا از تونل رد می‌شه؟**

آی‌پی عمومی، پرچم و نام کشور، شهر، ISP و یک بج مسیر ترافیک رو نشون می‌ده. وصل و قطع شدن VPN رو در حدود دو ثانیه تشخیص می‌ده، بدون اینکه در این فاصله هیچ API جیولوکیشنی رو صدا بزنه.

## چرا بج مهمه

فقط دیدن کشور جواب سؤال نیست. اگه خروجی VPN و ISP خودت هر دو به یک کشور برسن، یا تونل بالا باشه ولی ترافیک واقعاً ازش رد نشه، پرچم هیچی بهت نمی‌گه. بج می‌گه ترافیک چطور از دستگاه بیرون می‌ره:

| بج | معنی |
|---|---|
| `VPN` | مسیر خروجی روی یک آداپتور تونل است |
| `PROXY` | پروکسی سیستمی ویندوز تنظیم شده (v2rayN، Nekoray و مشابه) |
| `DIRECT` | آداپتور فیزیکی، بدون پروکسی |
| `OFFLINE` | مسیری به اینترنت نیست |

خط ISP نیمه‌ی دوم همین تصویره. اسم یک دیتاسنتر جایی که انتظار ISP خانگی داری (یا برعکس) معمولاً اولین نشانه‌ی اینه که مسیر ترافیک اونی نیست که فکر می‌کنی.

## تشخیص چطور کار می‌کنه

دو ایده بیشتر کار رو انجام می‌دن.

**تشخیص تغییر هیچ ترافیک اینترنتی تولید نمی‌کنه.** هر دو ثانیه یک امضای کاملاً محلی حساب می‌شه: آی‌پی محلی خروجی، که با `connect()` روی یک سوکت UDP گرفته می‌شه و فقط یک جستجو در جدول مسیریابی است و هیچ بسته‌ای نمی‌فرسته، به‌علاوه‌ی مقادیر پروکسی سیستمی در رجیستری ویندوز. VPN های حالت TUN اولی رو عوض می‌کنن و کلاینت‌های پروکسی سیستمی دومی رو. فقط وقتی این امضا تغییر کنه یک fetch جیولوکیشن اجرا می‌شه، آن هم با کمی تأخیر، چون شبکه موقع وصل شدن VPN چند بار بالا و پایین می‌شه. یک پولینگ ۱۵ ثانیه‌ای هم به‌عنوان تور ایمنی می‌مونه برای وقتی که آی‌پی عمومی عوض بشه ولی هیچ ردی روی سیستم نذاره، مثل عوض کردن سرور داخل خود برنامه‌ی VPN.

**مسیر از جدول مسیریابی خونده می‌شه، نه از روی رنج آی‌پی.** یک VPN که آدرس `10.x` می‌ده از یک شبکه‌ی محلی قابل تشخیص نیست. برای همین ویجت `GetAdaptersAddresses` رو صدا می‌زنه تا ببینه کدوم اینترفیس واقعاً صاحب آدرس خروجیه، بعد بر اساس `ifType` **و** نام آداپتور دسته‌بندی می‌کنه. آداپتورهای WireGuard و wintun خودشون رو `ifType 6` (اترنت) معرفی می‌کنن، پس چک کردن نوع به‌تنهایی از قلمشون می‌ندازه.

## امکانات

- بدون فریم، قابل جابه‌جایی، همیشه بالا (قابل خاموش کردن)، با سایز و شفافیت قابل تنظیم
- حالت پس‌زمینه‌ی شفاف: فقط متن و پرچم روی دسکتاپ شناور می‌مونن
- **قفل موقعیت**، تا یک کشیدن ناخواسته جابه‌جاش نکنه
- آیکون تری با پرچم کشور فعلی. تولتیپش مسیر، آی‌پی، ISP و نام آداپتور رو نشون می‌ده
- دابل‌کلیک برای کپی آی‌پی
- نام کشور موقع تغییر آی‌پی عمومی یک لحظه فلش می‌زنه
- کلید میان‌بر سراسری `Ctrl+Alt+I` ویجت رو از هر جایی احضار می‌کنه
- اجرای خودکار هنگام بالا آمدن ویندوز (رجیستری کاربر، بدون نیاز به دسترسی ادمین)
- سه سرویس جیولوکیشن به ترتیب امتحان می‌شن، با جابه‌جایی خودکار وقتی یکی جواب نده

### خودترمیمی

پنجره `overrideredirect` است، یعنی بدون فریم، بدون دکمه در تسک‌بار و بدون حضور در Alt+Tab. همین چیزیه که ازش یک ویجت می‌سازه، و همین هم خطرناکش می‌کنه: هر چیزی که چنین پنجره‌ای رو مخفی کنه، با روش‌های معمول برنمی‌گرده. یک نگهبان هر سه ثانیه اجرا می‌شه و:

- اگه پوسته‌ی ویندوز پنجره رو مخفی یا مینیمایز کرده باشه برش می‌گردونه. این با `IsWindowVisible` و `IsIconic` ویندوز چک می‌شه، چون `winfo_viewable()` خود Tk مخفی شدن در سطح پوسته رو نمی‌بینه
- اگه بعد از تغییر رزولوشن یا مانیتور بیرون از دسکتاپ مجازی افتاده باشه، برش می‌گردونه داخل
- هر چند وقت یک بار «همیشه بالا» رو دوباره اعمال می‌کنه
- نمی‌ذاره پنجره مخفی بمونه وقتی هیچ آیکون تری‌ای برای برگردوندنش وجود نداره
- بعد از ری‌استارت شدن `explorer.exe` آیکون تری رو دوباره می‌سازه، کاری که pystray خودش انجام نمی‌ده

## نصب و اجرا

ویندوز و پایتون ۳.۱۰ به بالا لازمه.

</div>

```bash
python -m venv venv
venv\Scripts\pip install -r requirements.txt
venv\Scripts\pythonw.exe ip_widget.pyw
```

<div dir="rtl">

`pystray` و `pillow` اختیاری‌ان. بدون اون‌ها ویجت دقیقاً همون‌طور کار می‌کنه، فقط آیکون تری نداره.

### ساخت فایل اجرایی

</div>

```bash
venv\Scripts\python.exe -m PyInstaller --clean --noconfirm VernaIPWidget.spec
```

<div dir="rtl">

خروجی یک فایل تکی بدون کنسول در `dist/VernaIPWidget.exe` است.

## تست‌ها

</div>

```bash
python -m unittest test_ip_widget.py -v
```

<div dir="rtl">

پارسرهای پاسخ جیولوکیشن، دسته‌بندی‌کننده‌ی مسیر ترافیک و بایندینگ رویدادها رو پوشش می‌ده. تست‌های بایندینگ به خاطر یک باگ واقعی نوشته شدن: هندلرها هم روی ویجت‌های فرزند بایند شده بودن هم روی toplevel، اما `bindtags` هر فرزند از قبل شامل toplevel است، پس هر حرکت دو بار اجرا می‌شد. منوی کلیک راست دو منوی روی هم باز می‌کرد و برای رسیدن به یک گزینه دو کلیک لازم بود. جایی که نمایشگری در دسترس نباشه، این تست‌ها تمیز رد می‌شن.

## تنظیمات

تنظیمات در `%APPDATA%\VernaIPWidget\config.json` ذخیره می‌شن: موقعیت، پله‌ی سایز، شفافیت، حالت شفاف، همیشه‌بالا و قفل. نوشتن اتمیک انجام می‌شه.

کنار همون فایل یک لاگ چرخشی هست: `%APPDATA%\VernaIPWidget\widget.log`. از منوی کلیک راست با گزینه‌ی *Open log folder* بازش کن. بیلد بدون کنسول هیچ stderr ی نداره، پس این فایل تنها منبع تشخیص مشکله.

## اعتبارها

آیکون‌ها از [Icons8](https://icons8.com). پرچم‌ها از [flagcdn.com](https://flagcdn.com). جیولوکیشن از [ip-api.com](https://ip-api.com)، [ipwho.is](https://ipwho.is) و [ipinfo.io](https://ipinfo.io)، همه با پلن رایگان و بدون نیاز به کلید API.
